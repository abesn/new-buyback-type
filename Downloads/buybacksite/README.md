# BuyBackSite — Phone Buyback SaaS Platform

A multi-tenant SaaS platform that gives phone buyback businesses a complete
white-label website with automated pricing, local SEO, and order management.

---

## Tech Stack

| Layer | Choice |
|---|---|
| Framework | Next.js 14 (App Router) |
| Language | TypeScript |
| Styling | Tailwind CSS + shadcn/ui |
| Database | PostgreSQL (via Railway) |
| ORM | Prisma |
| Cache / Jobs | Redis (via Railway) |
| Auth | NextAuth.js v4 (magic-link email) |
| Hosting | Railway |
| Custom Domains | Cloudflare SSL for SaaS |
| Emails | Resend (SMTP) |
| Shipping Labels | EasyPost |
| Pricing Data | eBay Browse API |
| Billing | Stripe |

---

## Prerequisites

Before you start, create accounts and collect API keys for:

- **Railway** — railway.app (host the app, PostgreSQL, Redis)
- **Resend** — resend.com (transactional emails / magic links) — free tier: 3k/mo
- **eBay Developer** — developer.ebay.com (pricing data, sandbox available)
- **EasyPost** — easypost.com (shipping labels, test mode available)
- **Stripe** — stripe.com (billing, test mode available)
- **Cloudflare** — cloudflare.com (custom domain mapping — needed for production)

## Local Development Setup

### 1. Clone and install

```bash
git clone <your-repo-url> buybacksite
cd buybacksite
npm install
```

### 2. Set up environment variables

```bash
cp .env.example .env.local
```

Open `.env.local` and fill in:

```
DATABASE_URL=         # From Railway PostgreSQL service
REDIS_URL=            # From Railway Redis service  
NEXTAUTH_SECRET=      # Generate: openssl rand -base64 32
NEXTAUTH_URL=         # http://localhost:3000
EMAIL_SERVER_HOST=    # smtp.resend.com
EMAIL_SERVER_PORT=    # 587
EMAIL_SERVER_USER=    # resend
EMAIL_SERVER_PASSWORD=# Your Resend API key
EMAIL_FROM=           # no-reply@yourdomain.com
NEXT_PUBLIC_ROOT_DOMAIN= # buybacksite.com (your platform domain)
```

The remaining variables (Cloudflare, eBay, EasyPost, Stripe) can wait
until you build those modules. The app runs without them in development.

### 3. Set up Railway services locally (or use Railway tunnel)

**Option A — Railway tunnel (recommended):**
1. Install Railway CLI: `npm i -g @railway/cli`
2. `railway login`
3. `railway link` (link to your Railway project)
4. `railway run npm run dev` — auto-injects all Railway env vars

**Option B — Local PostgreSQL + Redis:**
1. Install PostgreSQL and Redis locally
2. Set `DATABASE_URL` and `REDIS_URL` in `.env.local`

### 4. Run database migrations

```bash
npm run db:migrate
```

This creates all tables from `prisma/schema.prisma`.

### 5. Seed the device catalog

```bash
npm run db:seed
```

Seeds:
- 4 condition grades (A/B/C/D)
- 3 device categories (Smartphone, Tablet, Laptop)
- 10 brands
- ~100 device models
- ~750 device variants (model × storage × carrier)

### 6. Create your platform admin account

After seeding, sign in at `http://localhost:3000/login` using your email.
Then run this in Prisma Studio to promote yourself to PLATFORM_ADMIN:

```bash
npm run db:studio
```

Find your user, change `role` from `STAFF` to `PLATFORM_ADMIN`.

### 7. Start development

```bash
npm run dev
```

Open `http://localhost:3000` — redirects to `/login`.

## Railway Deployment

### Initial deploy

1. Create a new Railway project
2. Add a PostgreSQL service (auto-injects `DATABASE_URL`)
3. Add a Redis service (auto-injects `REDIS_URL`)
4. Connect your GitHub repo
5. Add environment variables from `.env.example` (fill in real values)
6. Railway auto-deploys on push to `main`

The `railway.toml` config runs migrations automatically before each deploy:
```
buildCommand = "npm run db:migrate:prod && npm run build"
```

### Custom domain (platform domain)

1. In Railway: your service → Settings → Domains → Add domain
2. Add `app.buybacksite.com` (or your platform domain)
3. Railway provides a CNAME target — point your DNS record to it

## Custom Domain Mapping for Clients

See the detailed guide in `docs/custom-domains.md` (coming in Module 7).

**Short version:**
1. Client adds a CNAME: `www.theirdomain.com → proxy.buybacksite.com`
2. Your app calls the Cloudflare API to register the custom hostname
3. Cloudflare provisions SSL automatically (2–10 mins)
4. Middleware reads the `host` header and resolves to the correct tenant

## Multi-tenancy Architecture

Every table that holds tenant data has a `tenantId` column with:
- A non-null constraint
- An index
- Used in all WHERE clauses for every query

The middleware (`middleware.ts`) sets `x-tenant-slug` or `x-tenant-domain`
headers on every request. Server components read these headers to identify
which tenant's data to load.

**Redis cache keys:**
- `tenant:domain:{domain}` — 1hr TTL, custom domain → tenantId
- `tenant:slug:{slug}` — 1hr TTL, subdomain slug → tenantId
- `feed:json:{tenantId}` — 6hr TTL, invalidated on price sync
- `market:{variantId}` — 6hr TTL, eBay price data
